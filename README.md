# slaughter_lord — планировщик-дневник для Telegram

Личное приложение «всё в одном» во встроенном Telegram WebApp: задачи с умным
вводом дат, проекты и теги, привычки с сериями, дневник с настроением,
помодоро-таймер, статистика, календарь и канбан. Тёмное фэнтези-оформление
с режимами **КРОВЬ / КИСЛОТА / БЕЗДНА** и выбором акцентного цвета.

Данные хранятся на сервере (SQLite), авторизация — через подписанный Telegram
`initData`. Интерфейс остаётся отзывчивым даже на бесплатном хостинге, который
«засыпает»: экран рисуется мгновенно из локального кеша, а синхронизация
идёт в фоне.

## Что внутри

- **Храм** — сводка: задачи на сегодня, статистика, лента привычек
- **Арсенал** — задачи: умный ввод («завтра 09:00 обряд #ритуал !важно»),
  подзадачи, приоритеты, фильтры, архив, календарь, канбан
- **Алтарь** — привычки: сетка 28 дней, серии, полезные/вредные
- **Исповедь** — дневник: одна запись на день (перезапись, без дублей)
- **Летопись** — статистика + помодоро (25/50/15 мин)
- **Культ** — титул, подзаголовок, метка, акцент, режимы, управление проектами

## Технологии

- Python 3.13 + aiogram 3 (long polling) + aiohttp (WebApp и REST API)
- SQLite (WAL, индексы, батч-синхронизация)
- Чистый HTML/CSS/JS без сборки — ни одного фреймворка

## Быстрый старт (локально)

```bash
pip install -r requirements.txt
```

Заполните `.env` (токен берётся у [@BotFather](https://t.me/BotFather)):

```dotenv
BOT_TOKEN=ваш_токен
DEV_MODE=1          # для локальной проверки WebApp из браузера
WEBAPP_URL=http://localhost:8080
```

Запуск:

```bash
python bot.py
```

Откройте `http://localhost:8080` — в демо-режиме (localhost) работает вся
логика. В Telegram отправьте боту `/start` и откройте приложение кнопкой.

> Для Telegram WebApp нужен публичный HTTPS-адрес: поднимите туннель
> (`cloudflared tunnel --url http://localhost:8080` или ngrok) и впишите
> ссылку в `WEBAPP_URL`.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Интеграционные тесты покрывают подпись initData (HMAC с ключом WebAppData),
изоляцию пользователей, батч-синхронизацию, ETag/304, gzip, кеш-заголовки
статики и все REST-эндпоинты.

Инструменты (нужен работающий сервер):

```bash
python tools/smoke.py   # HTTP-смоук: статика, gzip, ETag, батч-синхронизация
node tools/e2e.js       # сквозной прогон UI в jsdom против живого сервера
```

e2e прогоняет интерфейс целиком: умный ввод, синхронизацию, календарь,
канбан, модалку, привычки, дневник, помодоро, проекты и офлайн-режим.

## Архитектура отзывчивости

Сервер:

- `/api/sync` — все изменения клиента одним запросом (атомарная транзакция);
- `/api/full` — условный GET: при совпадении ETag отвечает 304, не тратя
  время на сборку и передачу состояния;
- статика отдаётся из памяти с gzip и вечным кешем для версионных файлов;
- `/health` — дешёвый эндпоинт для мониторинга (не трогает базу).

Клиент:

- мгновенный старт из localStorage-кеша, сервер подтягивается фоном;
- каждое действие применяется локально сразу (оптимистично), в сеть уходит
  пачкой по таймеру 350 мс; при сбое операции возвращаются в очередь;
- списки пересобираются точечно (keyed-патчинг) — нет мерцания и прыжков
  скролла, а перерисовка выполняется один раз на кадр;
- CSS без backdrop-filter и «фиксированных» фонов: только transform/opacity.

## Переменные окружения

| Переменная         | По умолчанию          | Описание |
|--------------------|-----------------------|----------|
| `BOT_TOKEN`        | —                     | токен бота |
| `WEBAPP_URL`       | `RENDER_EXTERNAL_URL` | публичный HTTPS-адрес WebApp |
| `WEB_HOST`/`WEB_PORT` | `0.0.0.0`/`8080`   | привязка HTTP-сервера |
| `DATA_DIR`         | `./data`              | каталог SQLite (на Render — диск) |
| `DEV_MODE`         | `0`                   | доступ по `?user_id=` для разработки |
| `INIT_DATA_MAX_AGE` | `604800`             | срок жизни initData, сек |
| `ASSET_VERSION`    | `9`                   | версия статики для сброса кеша |
| `SELF_PING_SECONDS` | `0`                  | self-ping `/health`, сек (0 = выкл.) |

## Деплой на Render

1. Запушьте репозиторий и создайте Web Service из Dockerfile (есть
   `render.yaml` для blueprint-деплоя).
2. Задайте `BOT_TOKEN` в Environment. `WEBAPP_URL` подставится сам из
   `RENDER_EXTERNAL_URL`.
3. Постоянство данных: бесплатный тариф стирает файловую систему при
   рестарте. Клиент автоматически восстанавливает последнее состояние из
   локального кеша устройства, но для гарантии подключите Render Disk и
   укажите `DATA_DIR=/var/data`.
4. Пинг `.github/workflows/keepalive.yml` каждые 5 минут не даёт сервису
   спать. Надёжнее — бесплатный [UptimeRobot](https://uptimerobot.com)
   на `https://<сервис>.onrender.com/health` каждые 5 минут.
