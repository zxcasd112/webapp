# TASK//JOURNAL — Боевой дневник задач для Telegram

Telegram-приложение-дневник для записи задач с агрессивным, брутальным оформлением.
Запись, выполнение задач и кастомизация — всё происходит прямо во встроенном
Telegram WebApp. Данные хранятся **на сервере** (SQLite), а не в браузере,
поэтому дневник работает независимо от твоего компьютера.

## Возможности

- Запись, выполнение, удаление задач (как дневник)
- Фильтры: все / активные / выполненные
- Кастомизация:
  - заголовок и подзаголовок
  - метка задачи (ед.ч.) — склоняется автоматически
  - акцентный цвет (color picker)
  - режимы оформления: **КРОВЬ** (красный), **КИСЛОТА** (лаймовый), **БЕЗДНА** (фиолетовый)
- Агрессивный стиль: острые углы, текстура, жирная типографика
- Данные каждого пользователя хранятся на сервере в SQLite
- Авторизация через Telegram WebApp `initData` (HMAC-подпись)

## Стек

- Python + aiogram 3
- aiohttp (отдаёт WebApp и REST API)
- Telegram WebApp (HTML/CSS/JS)
- SQLite (хранение)

## Быстрый старт (локально)

1. Установите зависимости:

```bash
pip install -r requirements.txt
```

2. Получите токен у [@BotFather](https://t.me/BotFather) и вставьте в `.env`:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН
```

3. Запустите:

```bash
python bot.py
```

4. WebApp требует публичный HTTPS. Для локальной проверки можно открыть
`http://localhost:8080` в браузере (API будет использовать заглушку `?user_id=`).

> Полноценная работа в Telegram (кнопка WebApp) требует публичного HTTPS-URL,
> поэтому лучше сразу деплоить на хостинг (см. ниже).

## Деплой на Render (работает без твоего компьютера)

Так бот и веб-приложение живут в облаке, и тебе не нужно держать компьютер включённым.

### 1. Создай GitHub-репозиторий и загрузи код

```bash
git init
git add .
git commit -m "task journal"
# создай репозиторий на github.com, затем:
git remote add origin https://github.com/ВАШ_ЛОГИН/НАЗВАНИЕ.git
git push -u origin master
```

### 2. Подключи к Render

1. Зарегистрируйся на https://render.com (бесплатно), авторизуйся через GitHub.
2. Нажми **New → Blueprint** (или **Web Service**).
   - Если выбираешь Blueprint, Render сам прочитает `render.yaml`.
   - Если Web Service: репозиторий → **Runtime: Docker** → команда запуска не нужна (есть Dockerfile).
3. Render создаст сервис и задаст **2 переменные окружения** (их нужно заполнить вручную):
   - `BOT_TOKEN` — твой токен бота
   - `WEBAPP_URL` — https-адрес твоего сервиса. Он появится после первого деплоя
     (вид `https://task-journal.onrender.com`). Впиши его и нажми Deploy повторно.
     Либо оставь пустым — код сам подставит `RENDER_EXTERNAL_URL`.

### 3. Настрой бота

У @BotFather выполни `/setdomain` и укажи адрес сервиса
(например `task-journal.onrender.com`) — это разрешает кнопку WebApp.

### 4. Готово

Напиши `/start` боту и открой дневник кнопкой. Приложение работает 24/7 в облаке.

## Важно про хранение данных (SQLite)

На бесплатном тарифе Render контейнер — эфемерный: при перезапуске/редеплое
файл БД может быть удалён. Для личного дневника это обычно некритично.
Если хочешь гарантированное сохранение:

- Добавь **Persistent Disk** к сервису на Render (платный тариф) и укажи путь `/app/data`,
- либо переведи хранение на внешнюю БД (например, бесплатный PostgreSQL от Render),
  поменяв `db.py`.

## Структура

```
bot.py            # aiogram-бот + aiohttp-сервер (WebApp + REST API)
db.py             # SQLite-хранилище (задачи и настройки пользователей)
config.py         # чтение конфигурации (BOT_TOKEN, WEBAPP_URL, Render env)
web/index.html    # разметка WebApp
web/style.css     # агрессивный стиль
web/app.js        # логика дневника, кастомизации и синхронизация с API
Dockerfile        # образ для Render / любого контейнерного хостинга
render.yaml       # опциональный конфиг Blueprint для Render
.env              # локальные токены (не коммитится)
```

## REST API

- `GET /api/state?initData=...` — получить дневник пользователя
- `POST /api/state?initData=...` — сохранить дневник (JSON: title, sub, label, accent, mode, tasks)
